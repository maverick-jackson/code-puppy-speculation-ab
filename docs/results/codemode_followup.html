Code mode, actually batching.

The original A/B found code mode made Code Puppy slower: models wrapped one tool call per run_code snippet and paid an extra round trip each time. We fixed the prompt, the return values and two harness bugs, then measured again, including the long, sub-agent-heavy work code mode was built for.

TL;DR

  • Snippets carry real work now. Tool calls per run_code went 1.60 → 3.19 (luna) and 2.03 → 2.74 (sol); single-call snippets dropped from 58% to 36% (luna). Sandbox errors fell 0.42 → 0.04 per task (sol).
  • Fewer round trips at equal accuracy. On long single-agent tasks code mode needs 7.5 model requests vs 11.4 without it (sol) at the same success rate and wall time; luna uses 30% fewer input tokens.
  • Sub-agents are where it shines. One run_code fans out all four sub-agents at once. sol finishes delegation tasks in 89s vs 217s (counting only finished runs; with its one 900s timeout, no code mode averages 285s) with 19.5 vs 43.1 total requests and 99% vs 91% of answer parts right.
  • Short tasks are a wash on wall time. Code mode still carries per-request prompt overhead; for luna it costs more input tokens than plain tool calling on 10 to 60 second tasks.
  • Two real Code Puppy bugs found by the benchmark, both fixed and merged: nested results spilled to handle strings inside the sandbox (#1013), and sub-agents had no output bounds at all (#1014).

What changedCode Puppy PRs #1013 and #1014, both merged into main

merged#1013

Teach batching, return whole values

  • Guidance rewritten around write programs, not single calls: batch, chain, loop, filter in code, absorb errors, with two type-clean multi-call examples.
  • Honest sandbox facts: no Path.glob, os.walk, subprocess; next(genexpr) raises; narrow str | None fields; check error instead of or "".
  • Batching note appended to the run_code tool description.
  • Nested tool results stay whole inside the sandbox; only what reaches the model is bounded.
  • read_file returns whole files in code mode instead of content=None.
merged#1014

Bound sub-agent outputs

  • Sub-agents were built without the main agent's ToolOutputLimits and response clamp.
  • Once the sandbox could read whole files, a single sub-agent return reached 294,877 chars.
  • Fix wires the same bounds into the sub-agent site: largest return now 9,845 chars, luna sub-agent context 89.0k → 34.7k tokens per session.

Bugs the benchmark caught

Spill handles inside the sandbox

Any nested tool result over 10k chars came back to the snippet as a "[Tool output too large ...]" string instead of a dict, breaking r["content"] and forcing extra round trips. Fixed in #1013.

Big files read as empty

read_file refused files over 10k tokens with content=None; snippet code turned that into "" and silently undercounted (8 vs 9 importers). Fixed in #1013, plus an off-by-one in the token field.

Sub-agents without output bounds

Sub-agents never had ToolOutputLimits. Returns of up to 294,877 chars landed in context whole. Fixed in #1014.

Our own example failed type checking

Iteration 2 taught sorted({m["file_path"] ...}); the sandbox type checker rejects it because the field is str | None. Half of that batch's errors. Fixed in iteration 3.

Graders reading wrapped stdout

Long ANSWER lines wrap at terminal width in rendered output, so 16-field answers looked wrong. Long tasks are graded from the transcript's final text.

Sandbox gaps

No Path.glob, os.walk, sys.path, subprocess; generator expressions are lists. Now stated up front instead of discovered by failing.

Method and caveats

  • Harness: headless code-puppy -p, one fresh working copy and isolated config / cache / state / data dirs per run. Only the ChatGPT OAuth token and model list are shared (symlinked; tokens are written in place). Sub-agents are pinned to the run's model, and every sub-agent session is captured.
  • Tasks: the 20 tasks and graders from the original A/B, unchanged. The 10 long tasks are composed from them, so their answer keys and hidden tests are reused; each was validated (bugged copy fails every part, reference fixes pass every part).
  • Variants: off = main with code mode disabled, base = code mode before #1013, new = after #1013, fix = after #1014.
  • Caveats: 10 runs per long-task cell. Within each batch, variants were shuffled together; the short-task off runs and the long-task fix runs were separate batches, so time-of-day effects are not controlled for those comparisons. Two OpenAI models through ChatGPT OAuth only. GLM 5.3 (served by vLLM) was tested and dropped: at ~20 tokens/s it timed out on most long code-mode runs.
