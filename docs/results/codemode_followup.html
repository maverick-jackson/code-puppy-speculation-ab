Read it this way: code mode cuts model round trips in every workload, because each request does 1.8 to 4.8 tool calls instead of 1.0 to 1.9. Whether that turns into less wall time and fewer tokens depends on the model and the workload: a code-mode request also carries -3.5k to 4.0k more input tokens than a plain one (the run_code description with every sandbox function signature, plus larger snippet results), which short tasks rarely earn back. Across all 30 tasks, sol gets faster on 18 and luna on 9.

Method and caveats

  • Off is code-puppy main with enable_speculative_code_mode = false. On is main after #1013 (short and long tasks) and after #1014 (delegated tasks; #1014 only changes sub-agents).
  • Headless code-puppy -p, one fresh working copy and private config / cache / state / data per run; sub-agents pinned to the run's model. Short tasks are the original A/B's 20 tasks and graders; long tasks are composed from them (validated answer keys and hidden tests).
  • Runs per side: short tasks 40 off / 80 on per model; long 4 to 6 per workload per side. Short off and delegated on ran as separate batches, so time-of-day effects are not controlled for those cells.
  • Tokens and requests include every sub-agent. Wall time includes timed-out runs at 900s.
  • How code mode got here (prompt iterations, bugs fixed): docs/CODEMODE_FOLLOWUP.md.
